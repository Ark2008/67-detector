# WebSocket: спецификация главного экрана

Соединение открывается на время одной сессии демонстрации, после REST-вызова `POST /sessions` 

Endpoint: `ws://<host>/ws/sessions/{session_id}`

## Клиент → сервер

Одно сообщение на каждый обработанный кадр видео, даже если рука не найдена — пустой `hands` (обновляет `last_activity_at`).

```json
{
  "type": "frame",
  "timestamp_ms": 1730000000123,
  "hands": [
    {
      "handedness": "Right",
      "score": 0.98,
      "landmarks": [
        { "x": 0.51, "y": 0.42, "z": -0.03 }
        // ... 21 точка, порядок — как в MediaPipe Hand Landmarker
      ]
    }
  ]
}
```

- `hands`: массив длины 0, 1 или 2 — жест «шесть-семь» показывается двумя руками, обе передаются на backend и в CV-модуль.
- `x`, `y` нормализованы [0, 1], `z` — относительная глубина, как отдаёт MediaPipe.
- Частота отправки ограничивается фронтендом до ~15–20 кадров/с.

## Сервер → клиент

### `session_ready` — подтверждение после установления соединения

```json
{ "type": "session_ready", "session_id": "...", "status": "active", "score": 0 }
```

### `gesture_detected` — жест засчитан (счётчик, звук, анимация на фронте)

```json
{
  "type": "gesture_detected",
  "score": 4,
  "detected_at": "2026-11-05T12:00:03.210Z",
  "cooldown_ms": 1500
}
```

`cooldown_ms` — информативное поле для UI; защита от повторного счёта всегда на сервере (см. ниже).

### `session_state` — смена статуса сессии (например, сервер закрыл по таймауту)

```json
{ "type": "session_state", "status": "timeout", "score": 7, "ended_at": "..." }
```

После `session_state` с `status != "active"` сервер закрывает соединение.

### `error` — ошибка обработки кадра/сессии (соединение не закрывается, кроме `session_not_found`)

```json
{ "type": "error", "code": "invalid_payload", "message": "landmarks length != 21" }
```

Коды: `invalid_payload`, `session_not_found` (сессия уже завершена/не существует — закрывает соединение), `internal_error`.

## Защита от двойного счёта (анти-дребезг)

Правило — на сервере, не в CV-модуле (см. [architecture.md](architecture.md)):

1. Сервер держит на сессию буфер последних N кадров и передаёт его в `detect_gesture` при каждом новом кадре.
2. Если `detect_gesture` вернул `gesture == "six_seven"` и с момента последнего засчитанного жеста прошло ≥ `COOLDOWN_MS` (константа backend, ориентир 1500 мс) — засчитывается: `sessions.score += 1`, пишется строка в `gesture_events`, клиенту уходит `gesture_detected`.
3. Если жест распознан, но cooldown не истёк — событие отбрасывается без записи и без отправки клиенту.

## Жизненный цикл соединения

1. Фронт: `POST /sessions` → получает `session_id`.
2. Фронт: открывает WS на `session_id`, запрашивает камеру, начинает стрим кадров.
3. Пока активна — кадры туда, `gesture_detected` обратно.
4. «Стоп»: фронт шлёт `POST /sessions/{id}/stop`, сервер переводит сессию в `stopped`, присылает в сокет `session_state` и закрывает его.
5. Если вкладка закрылась без «Стоп»: сокет рвётся без сообщения, backend по `last_activity_at` закрывает сессию таймаутом (фоновая задача).
