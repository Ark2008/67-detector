# Как работать с репозиторием

## Ветки и Pull Request

Основная ветка проекта — `main`. Каждую задачу начинайте от актуальной `origin/main` в отдельной ветке. Не пушьте изменения напрямую в `main`.

```bash
git fetch origin
git switch -c feature/short-description origin/main
```

Используйте имя ветки по смыслу задачи: `feature/...` для новой функции, `fix/...` для исправления, `docs/...` для документации, `chore/...` для технических изменений. В имени используйте короткие слова на английском через дефис, например `feature/game-screen`.

Порядок работы:

1. Сделайте изменения в своей ветке и проверьте затронутую часть проекта.
2. Запушьте ветку: `git push -u origin <имя-ветки>`.
3. Создайте Pull Request **из своей ветки в `main`**. Кратко опишите, что сделано и как проверено.
4. Назначьте ревьювером **Lileeid**.
5. Исправьте замечания в той же ветке. После одобрения ревью объедините PR с `main`.

Если задача меняет обмен данными между frontend, backend и CV, согласуйте контракт с участниками затронутых модулей и обновите документацию в том же PR.

## Сообщения коммитов

Формат: `type(scope): краткое описание`.

- `type`: `feat`, `fix`, `docs`, `test`, `refactor` или `chore`.
- `scope`: затронутый модуль, например `frontend`, `backend`, `cv` или `docs`. Если изменение общее, scope можно опустить: `chore: ...`.
- Описание пишите коротко, в настоящем времени, без точки в конце. Один коммит — одно логическое изменение.

Примеры:

```text
feat(frontend): add game screen layout
fix(backend): handle invalid websocket message
docs: clarify gesture result contract
```
